# Extraction Ops 学习项目总览

## 项目定位

本项目基于当前目录中的 Lyra Starter Game（Unreal Engine 5.8），目标是做出一个可运行、可讲解、可展示的 2-4 人多人撤离射击 Vertical Slice。

最终作品不追求内容规模，而追求一条完整且可信的链路：

```text
登录 -> 大厅 -> 加入对局 -> 角色与武器 -> 搜刮物资 -> 背包 -> 撤离/死亡
  -> 服务端结算 -> 业务后台持久化 -> 返回大厅
```

项目的个人定位是：

> 以游戏后台和分布式系统为纵深，补齐 UE 客户端、多人网络和游戏玩法，使用 AI 工具提升研发效率。

## 当前工程事实

- 工程文件：`LyraStarterGame.uproject`
- 引擎版本：`5.8`
- C++ 模块：`LyraGame`、`LyraEditor`
- 已启用的重要能力：`GameplayAbilities`、`ReplicationGraph`、`CommonUI`、`EnhancedInput`、`GameFeatures`、`OnlineServices`、`ShooterCore`、`ShooterMaps`、`ShooterTests`
- 已提供的构建目标：`LyraClient`、`LyraServer`、`LyraEditor` 及 Steam/EOS 变体
- 主要代码位置：`Source/LyraGame`

## 统一工作规则

1. 每周开始前创建 `week-XX` 分支或标签，并记录本周基线。
2. 优先写 C++ 核心逻辑，Blueprint 负责表现、组合和快速配置。
3. 新代码尽量放在独立的 `ExtractionOps` GameFeature 插件中，减少直接改动 Lyra 核心代码。
4. 每个功能必须同时记录：客户端职责、游戏服务器职责、业务后台职责、失败行为。
5. 每周至少保留一个可运行版本和一个屏幕录制片段。
6. 不以“代码写完”为验收，而以“能复现、能解释、能演示”为验收。

## 最终验收

最终版本需要满足：

- 两个客户端能通过 Dedicated Server 进入同一局；
- 客户端完成移动、射击、受伤、死亡、拾取和撤离；
- 角色和关键结果由服务器权威确认；
- 玩家资料、库存和结算由 Go 后台保存；
- 重复提交结算不会重复发奖；
- 断线重连后能恢复到合理状态；
- 能展示一次网络延迟/丢包实验和一次性能分析；
- 有一份面向面试官的架构说明，能清楚说明每个模块为什么存在。
