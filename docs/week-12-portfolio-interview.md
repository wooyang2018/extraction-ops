# 第 12 周：作品集包装与面试验收

## 本周目标

把前 11 周整理为陌生人能运行、能理解、能验证和能追问的求职作品。交付物包括最短启动路径、3 分钟真实演示、架构与时序图、性能/故障证据、简历描述、5 分钟讲解稿和模拟面试答案。

## 与总蓝图同步：作品质量和外测门槛

包装不能替代可玩性验证。最终至少邀请 8 名未参与开发的测试者，每人玩 3 局，并记录：

- 第二局起能否无需提示解释终端、Threat 与撤离关系；目标至少 70%；
- 能否复述一次真实的“继续扫描还是撤离”决策；目标至少 60%；
- 乐趣与紧张感评分中位数是否达到 4/5；
- 哪个音频/UI/AI 行为让其理解 Threat，哪个地方造成误解；
- 每局时长、终端数量、死亡/撤离结果和明显故障。

3 分钟视频优先展示本项目身份：终端 1 解锁撤离、玩家继续启动终端 2、Threat AI 侧翼施压、玩家带战利品撤离。网络、后台和性能证据紧随其后。不要让通用 Lyra 射击占据大部分时长。

## 前置条件与周门槛

- 第 11 周端到端冒烟、重连和 Settlement 一致性全部通过。
- 本周不增加新玩法；发现关键功能失败时回到对应周修复并重跑测试。
- 不把 Lyra 原有能力描述为自己从零实现，不把本地 MVP 描述为生产系统。

## 工作单元 1：仓库边界与最短复现

### 1.1 清理检查

只通过正常编辑移除已确认无用的实验代码/文档；不要清理不属于本项目的用户文件。检查并排除：绝对路径、Token/密钥、SQLite data、Saved/Intermediate/Binaries、无法运行的半成品、过期截图。

运行密钥和路径搜索，逐项人工判断，不把测试用 `player_id` 误报为密钥。确认公开仓库不分发 Lyra 原始/授权受限 Content，并链接 `asset-bootstrap.md`；同时确认 `Plugins/GameFeatures/ExtractionOps/Content/**` 中的自研 GameFeatureData、Blueprint 和其他可分发资产已经进入版本控制。

### 1.2 写“最快成功路径”

根 README 首屏流程必须是：安装依赖 → 初始化 Lyra 资源 → 配置环境变量 → 启动 Backend/Server/两个 Client → 登录/进局 → 完成测试流程 → 正常关闭。每条命令可复制，不依赖个人路径。

从新的 PowerShell 会话按 README 完整执行一次，记录总耗时和所有隐藏前置。任何口头补充都必须写回 README。

## 工作单元 2：架构与工程证据

制作一张总架构图，明确：UE Client、Dedicated Server、Go Backend、SQLite、Lyra/ExtractionOps 边界和数据权威。每条箭头标协议/数据，不画没有实现的云组件。

制作三张时序图：登录/Room/分配/Join；Fire/Server 校验/Damage/复制；Extract/Settlement transaction/重复响应。每张包含 request_id/match_id/run_id、失败或重试路径和最终权威。

整理证据索引：网络延迟/丢包、非法射击、双人争抢、断线恢复、10 次并发 Settlement、Server 心跳过期、Insights 前后对比。每项链接到日志片段、截图或报告，并注明测试条件。

## 工作单元 3：录制 3 分钟演示

先写镜头清单并彩排两次，最终尽量单次完成主要流程：

```text
00:00–00:20  目标、技术栈、Lyra 扩展边界
00:20–01:05  两客户端进局、射击、搜刮和争抢
01:05–01:35  背包、装备、死亡掉落与撤离
01:35–01:55  断线和同一 Run 恢复
01:55–02:20  撤离结算与重复请求幂等
02:20–02:45  架构、日志关联和性能前后数据
02:45–03:00  项目限制与可扩展方向
```

录制前清空旧日志、固定窗口布局、关闭通知、隐藏 Token。不要用剪辑掩盖等待无限、连接失败或状态错误；可加字幕压缩正常加载时间，但保留真实可运行证据。

## 工作单元 4：README、简历和口述稿

README 按顺序包含：项目一句话、演示、已实现功能、架构、最快启动、测试、目录、Lyra 与个人贡献、限制、文档索引。指标必须附硬件/人数/场景。

简历只写已验证内容，使用“动作 + 技术决策 + 结果/证据”：

```text
多人撤离射击 Vertical Slice | UE5 / C++ / Lyra / GAS / Go
- 扩展 Lyra GameFeature，完成 1–2 人合作专服战斗、搜刮、背包、Threat 与撤离闭环。
- 由 Dedicated Server 权威校验伤害、物品和撤离，以短期 Ticket 连接 Go 控制面。
- 使用稳定 ID、SQLite transaction/唯一约束实现重连恢复和结算幂等。
- 使用结构化日志、Unreal Insights 和网络分析完成故障定位及量化优化。
```

5 分钟稿固定结构：30 秒目标 → 60 秒架构/边界 → 60 秒网络权威 → 60 秒重连/幂等 → 45 秒测试/性能 → 30 秒失败与取舍 → 15 秒限制。所有数字与仓库证据一致。

## 工作单元 5：陌生人复现与模拟面试

找一位未参与项目的人，或使用全新目录/Windows 用户视角，只提供仓库 URL/README。记录对方在哪一步停住、耗时、错误和文档缺口；修正文档后重新从头验证，不替对方口头操作。

准备并录音回答至少 10 题：Dedicated vs Listen、RPC vs Replication、预测失败、伤害防伪、重连不重复 Pawn、DB Commit 后响应丢失、Settlement 幂等、Server Tick 定位、背包权威、扩展多实例/多区域。

每题使用“结论 → 当前实现证据 → 取舍 → 扩展方向”，控制 60–90 秒。无法回答的问题回到代码/报告核对，不编造生产经验。

## 实现原理

作品集的目标是降低验证成本：运行说明证明可复现，视频证明可工作，图证明理解，故障/性能报告证明工程方法，限制说明证明判断力。功能数量不如一条可信闭环和可追踪证据重要。

## 常见问题与停止条件

- README 很长仍跑不起来：优先修最短路径，把背景移到 docs。
- 图比实现先进：删除未实现组件，不用“未来架构”冒充现状。
- 指标漂亮但无条件：补硬件、构建、场景和时长，否则删除数字。
- 把 Lyra 功能说成自研：明确基线、扩展点和个人代码。

陌生人无法复现核心流程或视频依赖隐藏手工修复时，作品集不算完成。
